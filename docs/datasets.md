# NYC TLC datasets

Use Yellow Taxi trip records and the taxi zone reference table from the
[NYC TLC trip record data page](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page).
The default exercise input is
[January 2024 Yellow Taxi](https://d37ci6vzurychx.cloudfront.net/trip-data/yellow_tripdata_2024-01.parquet).
The reference file is the
[taxi zone lookup CSV](https://d37ci6vzurychx.cloudfront.net/misc/taxi_zone_lookup.csv).

Keep the downloaded data unmodified under [the local data directory](../data/README.md).
A file's month identifies the TLC publication input. Individual pickup and drop-off
timestamps can fall outside that month. Treat these timestamps as local wall-clock
times in PostgreSQL. Keep them free of timezone conversion.

| Source field | PostgreSQL column | Type or unit |
| --- | --- | --- |
| Generated by PostgreSQL | `trip_id` | Bigint surrogate key |
| `VendorID` | `vendor_id` | Integer code |
| `tpep_pickup_datetime` | `pickup_datetime` | Timestamp without time zone |
| `tpep_dropoff_datetime` | `dropoff_datetime` | Timestamp without time zone |
| `passenger_count` | `passenger_count` | Integer count |
| `trip_distance` | `trip_distance` | Double precision, miles |
| `PULocationID` | `pickup_location_id` | Integer zone code |
| `DOLocationID` | `dropoff_location_id` | Integer zone code |
| `payment_type` | `payment_type` | Integer code |
| `fare_amount` | `fare_amount` | Numeric, USD cents precision |
| `tip_amount` | `tip_amount` | Numeric, USD cents precision |
| `total_amount` | `total_amount` | Numeric, USD cents precision |

Reject rows with missing or unusable pickup or drop-off timestamps, reversed
timestamps or negative trip distance. Keep zero distance, missing values in
nullable columns, unknown zone IDs and negative fare adjustments. Report how many
rows were read and accepted. TLC provides no reliable natural trip ID for this
exercise. Similar-looking records can describe different trips.

The zone CSV has a unique location ID per row plus borough, zone name and service
zone. Keep one row per location ID in PostgreSQL. Later reports can use an
`Unknown` category when a trip's zone has no matching lookup row.
